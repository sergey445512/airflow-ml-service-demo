# Живая карта ML-платформы

Откройте **http://localhost:8090**. Карта работает как отдельный контейнер `architecture-map`: обновляется каждые 3 секунды и ведёт к настоящим интерфейсам сервисов по нажатию на узел.

## Что показывать в гайде

1. Откройте карту. Зелёные точки означают, что сервис отвечает на проверку; жёлтые — что источник состояния недоступен или нет свежего измерения. Число запросов берётся из `/metrics` работающего inference-сервиса.
2. Запустите любой `demo_01`–`demo_05` в Airflow. Карта автоматически покажет активный DAG, а после завершения — самый недавний запуск. В блоке **«Запуски DAG»** можно выбрать конкретный DAG или вернуться в режим «Авто». Учебные `demo_01`, `demo_02`, `demo_03` показывают задачи, retry и восстановление, но не записывают модель в MLflow.
3. Нажмите **«Обучить модель»** на карте, чтобы запустить `demo_04_train_and_publish`. Он регистрирует кандидата в MLflow и сохраняет файлы модели в S3/RustFS, но **не переключает** production-модель. Для демонстрации переключения назначьте новой версии alias `production` в MLflow: карта покажет версию, которую реально загрузил inference.
4. Нажмите **«Пакетный скоринг»**. Для DAG `demo_05_weekly_batch_scoring` карта покажет фиксацию версии в MLflow, чтение модели из S3, чтение клиентов и запись оценок в PostgreSQL. Выберите его в списке DAG-ов; результат появится в блоке **«Последний пакетный скоринг»**. Расписание — каждый понедельник в 03:00 UTC, ручной запуск доступен в любой момент.
5. Сделайте push в `main` и смотрите GitHub Actions. CI собирает и проверяет стек; CD готовит неактивную копию ML-сервиса, проверяет прогноз и переключает прокси. При изменении DAG или связанного кода отдельный шаг выкатывает образ Airflow. Во время релиза ML-сервиса запросы продолжают идти через старую копию; MLflow и хранилища не перезапускаются.

Для объяснения онлайн-запроса нажмите на линию **Трафик → Inference**, затем **Inference → Postgres**. Активность показана только подсветкой пунктира: движущихся подписей и точек нет. Нажать можно на всю траекторию, включая промежутки пунктира; описание выбранной связи появляется в боковой панели. Там же показаны последний сохранённый прогноз и агрегированные метрики Prometheus. Подсветка определяется наблюдаемыми данными и стадиями DAG, а не трассировкой отдельного запроса.

События CI для приватного репозитория передаются локальным скриптом `scripts/observe-actions.ps1`, который использует уже настроенный `gh` и отправляет карте лишь статус запуска. Его можно запустить в скрытом окне через `scripts/start-runner.ps1`. Если наблюдатель не работает, карта прямо показывает отсутствие данных GitHub; остальные сервисы и DAG продолжают отображаться. Пароль Airflow карта читает внутри Docker из существующего volume и не отправляет в браузер.

Запуск карты отдельно от остальных сервисов:

```powershell
docker compose build architecture-map
docker compose up -d --no-deps --wait architecture-map
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-runner.ps1
```

Карта использует локальные адреса и демо-учётные записи стенда. Она предназначена для показа архитектуры на своём компьютере, а не для размещения в публичной сети.
