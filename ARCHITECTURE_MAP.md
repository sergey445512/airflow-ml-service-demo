# Живая карта ML-платформы

Откройте **http://localhost:8090**. Карта работает как отдельный контейнер `architecture-map`: обновляется каждые 3 секунды и ведёт к настоящим интерфейсам сервисов по нажатию на узел.

## Что показывать в гайде

1. Откройте карту. Зелёные точки означают, что сервис отвечает на проверку; жёлтые — что источник состояния недоступен или нет свежего измерения. Число запросов берётся из `/metrics` работающего inference-сервиса.
2. Запустите любой `demo_01`–`demo_04` в Airflow. Карта автоматически покажет активный DAG, а после завершения — самый недавний запуск. В блоке **«Запуски DAG»** можно выбрать конкретный DAG или вернуться в режим «Авто». Учебные `demo_01`, `demo_02`, `demo_03` показывают задачи, retry и восстановление, но не записывают модель в MLflow.
3. Нажмите **«Запустить демо DAG»** на карте, чтобы запустить `demo_04_train_and_publish`. Он регистрирует кандидата в MLflow и сохраняет файлы модели в S3/RustFS, но **не переключает** production-модель. Для демонстрации переключения назначьте новой версии alias `production` в MLflow: карта покажет версию, которую реально загрузил inference.
4. Сделайте push в `main` и смотрите отдельную ветку GitHub Actions. CI собирает и проверяет образ, CD обновляет только `inference` и `traffic`; Airflow, MLflow и хранилища продолжают работать. Во время сборки счётчик запросов на карте продолжает меняться. При самой замене одного контейнера возможен короткий перерыв; стенд пока не реализует бесшовное переключение двух реплик.

Для объяснения онлайн-запроса выберите на карте **Бэкенд → МЛ-сервис** и обратную линию. Узел «Бэкенд» в демо изображает генератор запросов. После обнаружения нового успешного прогноза карта однократно воспроизводит цикл: `POST /predict` с признаками → запись признаков и прогноза в Postgres → ответ с вероятностью оттока. Подпись движется только к получателю и исчезает вместе с подсветкой линии. Боковая панель показывает последний реально сохранённый прогноз. Это визуализация по наблюдаемым счётчикам, а не точная трассировка времени отдельного HTTP-запроса.

Для поиска похожих клиентов генератор раз в 12 запросов отправляет новый `POST /neighbors`, а следующим запросом повторяет его. Первый показывает `GET` к Redis → `MISS` → поиск в Qdrant → результат → `SETEX` в Redis → ответ клиенту. Второй показывает `HIT` и сразу ответ, без Qdrant. Карта воспроизводит только ветку, подтверждённую метриками cache hit/miss. Prometheus отдельно показывает `GET /metrics` и ответ при успешном сборе. Нажать можно на всю траекторию связи, включая пустые промежутки пунктира; подробности есть в списке связей. Подпись стадии CI/CD появляется только во время сборки или выкладки.

События CI для приватного репозитория передаются локальным скриптом `scripts/observe-actions.ps1`, который использует уже настроенный `gh` и отправляет карте лишь статус запуска. Его можно запустить в скрытом окне через `scripts/start-runner.ps1`. Если наблюдатель не работает, карта прямо показывает отсутствие данных GitHub; остальные сервисы и DAG продолжают отображаться. Пароль Airflow карта читает внутри Docker из существующего volume и не отправляет в браузер.

Запуск карты отдельно от остальных сервисов:

```powershell
docker compose build architecture-map
docker compose up -d --no-deps --wait architecture-map
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-runner.ps1
```

Карта использует локальные адреса и демо-учётные записи стенда. Она предназначена для показа архитектуры на своём компьютере, а не для размещения в публичной сети.
